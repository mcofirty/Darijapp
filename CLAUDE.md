# Darijaapp

Ce fichier est la mémoire du projet. Lis-le en entier au début de chaque session et mets-le à jour à la fin de chaque tâche, en suivant les règles de la dernière section. Il doit toujours décrire le projet tel qu'il est aujourd'hui.

## Projet

- PWA personnelle pour apprendre le vocabulaire du darija marocain à l'oral, par sessions ludiques de 5 à 10 minutes par jour.
- Utilisateur unique : un francophone débutant qui ne lit pas l'arabe et utilise l'appli sur iPhone.
- Objectif : 300 mots et expressions en 3 mois, prononciation des sons ع (3), ح (7), ق (9), خ (kh), غ (gh).
- Spécifications fonctionnelles complètes : `docs/cahier-des-charges.md`. En cas de doute sur un comportement, c'est la référence.

## Principes non négociables

- 100 % local : aucun serveur, aucun compte, aucun service externe, aucune clé d'API.
- Tout doit être réalisable par du code dans ce repo.
- Rien de payant ni de verrouillé : toutes les leçons, sessions et quiz sont accessibles à tout moment.
- Fonctionne hors ligne après le premier chargement.
- La voix de l'utilisateur et sa progression ne quittent jamais l'appareil.
- Mobile d'abord (iPhone, Safari, PWA installée sur l'écran d'accueil), interface en français.

Ne modifie jamais cette section sans demande explicite.

## Stack

| Brique | Choix |
| --- | --- |
| Interface | React + Vite + TypeScript, Tailwind CSS, icônes Lucide (style SF Symbols) |
| Hors ligne | PWA via vite-plugin-pwa |
| Stockage | IndexedDB via Dexie |
| Audio des mots | MP3 de la voix marocaine Jamal (`ar-MA-JamalNeural`) par l'API Azure Speech (offre gratuite F0), générés par `scripts/generate_audio.py` dans l'Action, dans `public/audio/<id>.mp3` ; secours : voix arabe de l'iPhone (`speechSynthesis`) tant qu'un MP3 manque, secours local mms-tts-ara (`--moteur mms`). Clés : secrets GitHub `AZURE_SPEECH_KEY` et `AZURE_SPEECH_REGION`, jamais dans le repo |
| Enregistrement | MediaRecorder |
| Score de prononciation | MFCC + DTW écrits dans `src/scoring/` (sans bibliothèque), rééchantillonnage à 16 kHz maison, réglage sur la voix de l'utilisateur ; score précis (expérimental, `src/scoring/sons/`) : modèle wav2vec2 XLSR-53 de Meta (phonétique de Common Voice, Apache 2.0) en ONNX int8, 355 Mo en 8 morceaux dans `public/modele/` (Action « Modèle »), lu par onnxruntime-web (WebAssembly, un fil), téléchargé depuis Profil et gardé dans Cache Storage (`darija-modele`), avec la voix de Jamal déjà analysée (`references.json`, 0,8 Mo) ; tests avec onnxruntime-node |
| Tests | Vitest |
| Publication | GitHub Pages, via la GitHub Action « Publier » (`.github/workflows/publier.yml`) ; MP3 par l'Action « Audio » (`.github/workflows/audio.yml`) |

## Commandes

```bash
npm run dev                         # serveur local (http://localhost:5173/Darijapp/)
npm test                            # tests Vitest
npm run build                       # build de production dans dist/
python scripts/generate_audio.py    # génère les MP3 manquants avec Azure (clés en variables d'environnement ; options --theme, --force, --apercu, --moteur mms)
```

Publication : chaque push sur `main` lance l'Action « Publier » (tests, build, mise en ligne sur https://mcofirty.github.io/Darijapp/, environ 2 min ; une publication en attente est remplacée par la suivante). Quand `src/data/` ou le script audio changent, l'Action « Audio » génère les MP3 manquants avec la voix Jamal (Azure, environ 20 fichiers par minute) sur la dernière version de `main`, commite ce qui est fait même si elle s'arrête en route (`github-actions[bot]`), la suivante reprenant ; à sa fin, « Publier » se relance seule (`workflow_run`) pour mettre les MP3 en ligne. Pense à faire `git pull` avant de travailler, l'Action pouvant avoir ajouté des MP3. Le script Azure n'a pas de dépendance (secours mms : `torch transformers` et ffmpeg). Azure et Hugging Face sont bloqués dans l'environnement cloud de Claude Code, ouverts sur GitHub Actions : la génération se fait toujours par l'Action. Lancées à la main (onglet Actions) : « Modèle » (`scripts/modele/xlsr.py` : télécharge, exporte en ONNX int8, évalue sur les paires ; case « enregistrer » pour l'écrire dans le repo) et « Voix de test » (`scripts/modele/voix_test.py` : les mots des paires par Mouna, Salma, Hamed et Ismael, dans `scripts/modele/voix-test/`, pour les tests seulement). Références du score précis : `npx tsx scripts/modele/references.ts` (ici, environ 10 min) après un changement de latin ou de MP3 ; `references.test.ts` signale une référence périmée.

Design : règles d'Apple (Human Interface Guidelines, iOS 26). Couleurs sémantiques système en clair et en sombre (`src/index.css` : fond groupé, cartes, libellés primaire/secondaire, séparateurs), couleurs principales du drapeau marocain : rouge #C1272D pour l'accent et les boutons, vert #006233 pour les réussites (`--accent`/`--vert` pour le texte, éclaircis en sombre ; `--accent-plein`/`--vert-plein` pour les fonds de boutons ; contrastes WCAG AA). Apparence clair/sombre réglable dans Profil (Automatique, Clair, Sombre) : attribut `data-theme` sur `<html>`, variante `dark:` de Tailwind redéfinie en conséquence. Typographie système SF Pro avec l'échelle iOS (classes `.t-grand-titre` à `.t-legende`, en rem sur le corps 17 pt, Dynamic Type via `-apple-system-body`). Chaque écran a un grand titre ; au défilement, le titre passe en petit au centre et le contenu s'efface sous un bord flou (`.bord-flou`, effet de bord d'iOS 26) ; le retour est un chevron seul dans un bouton rond en verre. Contenu en listes groupées façon Réglages, mesurées sur une capture de l'utilisateur (écran de 440 pt) : marge des pages 20 pt (`px-marge`), cellules de 56 pt minimum (`min-h-ligne`), texte à 20 pt du bord de la carte, séparateurs alignés sur le texte et arrêtés à 20 pt du bord droit, titres de section en 17 pt semi-gras gris sans majuscules, tuiles d'icônes colorées, chevrons. Angles d'iOS 26 (jetons `--radius-*` de `src/index.css`, classes `rounded-liste`…) : listes et cartes 26 px, tuiles d'icônes 8 px, réponses des exercices en capsule, logo à 22,37 % ; un conteneur qui entoure un bouton en capsule est concentrique (rayon du bouton + marge : panneaux en verre, carte Session du jour, alertes, aide à l'installation, carte « Thème » du Profil avec son contrôle segmenté, via la prop `arrondi` de `Section`) ; angles continus (`corner-shape: superellipse`) là où le navigateur les dessine, capsules exclues. Liquid Glass (`.verre` : verre clair au centre, bande de bord plus réfractante, liseré lumineux, légère dispersion colorée ; `.verre-fin` pour les petites commandes ; `.verre-epais` pour les alertes et la recherche, plus opaque pour rester lisible ; `.lentille-goutte` pour les curseurs pendant le geste) réservé aux commandes : barre d'onglets, boutons de barre (retour, série), croix et capsule de progression de la session, panneaux « Continuer » et du bilan, champ de recherche collant du Dictionnaire, alertes (composant `Alerte`, à la place de `window.confirm`) ; jamais sur le contenu. Contrôle segmenté façon iOS 26 : capsule grise, libellés sur une ligne (13 à 15 pt selon la largeur de l'écran), curseur en verre clair au repos (`.verre-curseur`) ; pendant l'appui ou le glissement, il devient une goutte de verre qui suit le doigt, puis revient avec un rebond. Interrupteur : la pastille devient une goutte de verre pendant l'appui. Une commande en verre grossit au toucher au lieu de pâlir. Aucune barre de défilement visible (`scrollbar-width: none`). Respect de Réduire les animations et Réduire la transparence.

Navigation : barre d'onglets flottante en verre dépoli, reproduite d'après la maquette de l'utilisateur (mesures sur un écran de 440 pt) : 62 pt de haut, marges de 21 pt, rail en retrait de 9 pt, lentille 10 pt plus large que l'onglet et en retrait de 4 pt, icônes pleines dessinées en SVG (boîte de 28 pt), libellés de 11 pt ; une lentille marque l'onglet actif et suit le doigt quand on glisse le long de la barre (étirement selon la vitesse, icônes grossies, retour élastique). Un balayage horizontal de la page change aussi d'onglet, sauf sur les zones marquées `data-sans-balayage`.

Fiche mot : latin en grand, arabe dessous (affiché par défaut, masquable dans Profil), traduction, note d'usage s'il y en a, boutons « Écouter » et « Ralenti » (0,75×), lecture automatique à l'ouverture, explication de prononciation, explication de chaque son particulier du mot, exemple avec son audio ; en bas, « Ajouter aux favoris » et « Signaler une erreur » (motif : la traduction, l'écriture, la prononciation).

Session du jour (style Duolingo, plein écran) : jusqu'à 8 révisions dues et 5 nouveaux mots dans l'ordre du programme. Chaque nouveau mot est présenté (« Nouveau mot ») puis exercé ; les nouveaux mots puis les révisions finissent par « Associe les paires » ; après les paires des nouveaux mots, les 2 premiers sont à prononcer (Dis-le ; sans nouveau mot, 2 révisions), puis une question « Distingue les sons » sur un son présent dans les mots de la session ; après les révisions, une « Construis la phrase » (sur une révision, sinon un nouveau mot) et un « Dis-le en darija » sur une révision en boîte 2 ou plus, puis un autre sur le premier nouveau mot, à retrouver de mémoire (option `rappel`) (aussi dans les leçons du Parcours ; « Mots difficiles » n'a que la phrase). Barre de progression, croix pour quitter, retour immédiat (vert « Bravo ! » ou rouge avec la bonne réponse, petit son, mot rejoué). Une question ratée revient en fin de session. Bilan avec confettis : XP, taux de réussite, série, et carte « Sauvegarder ma progression » si la dernière sauvegarde a 7 jours ou plus (ou jamais, dès 3 activités ; `sauvegardeConseillee`), dans tous les bilans. Sans révision ni mot nouveau : entraînement libre sur 8 mots vus, qui ne change pas la répétition espacée. Pas de cœurs ni de vies.

Exercices : Écoute et choisis, Traduis, Associe les paires, Distingue les sons (fait : « Quel mot entends-tu ? », 14 paires comme 9elb / kelb, 7al / khal, ghali / khali ; traduction montrée après la réponse ; hors répétition espacée), Quiz express (60 s), Dis-le (fait : mot, « Écouter » et « Ralenti », gros bouton micro (`BoutonMicro`) vide, en contour, quand il faut appuyer, plein avec une onde et un halo qui suit la voix quand il faut parler, arrêt seul après 0,8 s de silence ; score sur 100 dans un anneau qui se remplit, chiffre au centre, couleur selon la note (100 or, 90 vert foncé, 80 vert clair, 70 orange, 50 jaune, 1 rouge, 0 disque noir ; `couleurDuScore`), libellé ; avec le score précis, le mot son par son en pastilles (vert, orange, rouge) et, pour un son du darija raté, ce que le modèle entend à la place s'il s'agit d'une confusion courante (« Ton 7 : on entend plutôt un « h » »), plus l'explication du son ; « Mon essai », « Le modèle », « Réessayer », « Le score se trompe » qui inverse le résultat ; « Presque » rejoue le modèle, « À retravailler » le rejoue au ralenti et explique les sons difficiles du mot ; validé par « Continuer », jamais refait en fin de session ; auto-évaluation « Je l'ai bien dit » / « À retravailler » sans micro, micro refusé ou sans MP3 de référence, avec « Mon essai » et « Le modèle » quand on a pu s'enregistrer), Dis-le en darija (Dis-le inversé : seul le français, rien n'est lu avant l'essai ; « Indice » montre le début du mot (`3a…`), puis « Voir le darija » ; après l'essai, le darija se dévoile et le modèle est lu ; sans micro, « Montrer la réponse » puis auto-évaluation), Construis la phrase (l'exemple d'un mot, de 3 à 6 mots, est lu ; traduction affichée ; on touche ses mots, mélangés avec 2 intrus pris dans d'autres exemples, pour la reconstruire, un toucher les renvoie ; « Vérifier » ; l'ordre exact est exigé, ponctuation ignorée ; compte pour le mot dans la répétition espacée et revient en fin de session si ratée).

Mes mots (page cachée) : ouverte uniquement par le lien `https://mcofirty.github.io/Darijapp/#ajout`, sans entrée dans les onglets ni les menus. Formulaire à trois champs obligatoires (français, latin, arabe), validés par la translittération 3 7 9 kh gh ch ; liste de ses mots avec modification et suppression (seuls les mots ajoutés sur l'appareil, jamais ceux du programme), puis liste en lecture seule des mots du programme ; icône d'envoi sur chaque mot ajouté (feuille de partage de l'iPhone, sinon copie du lien), donc après l'avoir vu et corrigé, qui produit un lien `…/Darijapp/#mot=[latin, arabe, français, ajouté le]` (la page prévient que l'heure de l'ajout part avec le mot) : l'ouvrir affiche le mot, « Ajouté le 13 octobre 2026 à 9 h 37 » (heure du téléphone qui reçoit), et ne l'ajoute qu'après confirmation (jamais deux fois) ; la liste de ses mots montre aussi cette ligne ; sous le message d'accueil, un bouton « Ouvrir l'application » retire `#ajout` de l'adresse et affiche les onglets (sans rejouer la vidéo d'ouverture) ; un message d'accueil s'adresse à la personne qui ajoute les mots (demande de l'utilisateur, prénoms visibles dans le repo public). Les mots ajoutés passent en tête des nouveaux mots des sessions, entrent dans la répétition espacée, le dictionnaire et les leurres, et sont lus par la synthèse vocale. Ils restent sur l'appareil.

Aide à l'installation : à chaque ouverture dans Safari sur iPhone ou iPad (jamais dans l'appli installée, ni sur Android ou ordinateur, ni sur `#ajout` et `#mot=`), une feuille en verre monte du bas : logo, « Ajoute Darijaapp à ton écran d'accueil », phrase mise en avant « L'ajout à l'écran d'accueil enregistre ta progression. Dans Safari, elle peut être effacée. » (Safari efface les données d'un site non installé après 7 jours sans visite), 4 étapes (Partager, ou « ⋯ » d'abord sur iOS 26 ; « Sur l'écran d'accueil » ; « Ajouter » ; ouvrir depuis l'icône), bulle ronde « Ne plus afficher » et bouton « Compris ». Sans la bulle cochée, elle revient à l'ouverture suivante.

Animation d'ouverture : à chaque lancement à froid (pas sur `#ajout` ni `#mot=`), la vidéo de l'utilisateur (`public/lancement.mp4`, 3 s, sombre, sans son : logo, « Darija », « Le marocain, à l'oral d'abord. », « Projet indépendant réalisé par Romain Innocenzi ») joue en plein écran sur fond #0d0c0f, puis s'efface en fondu sur l'appli ; un toucher la passe ; avec Réduire les animations, ou si la vidéo ne démarre pas en 2 s (mode Économie d'énergie), l'image finale s'affiche 1 s. L'aide à l'installation attend sa fin.

Grammaire orale (Apprendre > Parler) : 6 fiches (négation ma…ch ; possessifs dari, darek ; présent en ka- ; futur ghadi ; passé ; questions wach, fin, chno…), chacune avec la règle en 3 phrases et 7 à 9 formes à écouter (latin, arabe, français, MP3 Jamal) ; « S'entraîner » : 5 questions sur 5 formes différentes (Traduis, Écoute et choisis, Construis la phrase s'il y a une forme de 3 à 6 mots, Écoute et choisis, Dis-le d'une phrase), leurres pris dans la leçon ; comptée comme un quiz (activité `grammaire` : XP, série, dirhams, pas de répétition espacée, pas de question refaite). Dialogues (Apprendre > Parler) : 8 scènes de 4 à 6 répliques (café, taxi, épicier, faire connaissance, chemin, restaurant, pharmacie, téléphone), 2 ou 3 à dire, accordées au genre du Profil (version `feminin` des répliques où l'on parle de soi ou à qui l'on s'adresse) ; liste avec le meilleur résultat (`2/3`) ; scène plein écran : « Écoute la scène » (bulles façon messagerie, l'autre à gauche, toi à droite, touchées pour réécouter, « Tout écouter » / « Arrêter »), puis « À toi de jouer » : les répliques de l'autre apparaissent et sont lues, chacune des tiennes est un Dis-le en darija d'une phrase (français seul, indice, score contre le MP3 de la réplique) validé par « Continuer », bulle cochée ou barrée ; « Terminer », bilan ; activité `dialogue` (XP, série, dirhams), meilleur résultat dans le profil (`dialogues`). Toutes les voix sont Jamal (voix Mouna refusée par l'utilisateur).

## Règles métier

- **Translittération** : 3 = ع, 7 = ح, 9 = ق, kh = خ, gh = غ, ch = ش ; 2 = ء (hamza, mots importés, non vérifié) ; accents permis dans les mots empruntés au français (supermarché, reçu). Appliquée partout, sans exception : chaque lettre arabe de cette liste a sa graphie latine dans le mot et l'exemple (vérifié par `data.test.ts`). ق prononcé « g » s'écrit g / ڭ. L'article assimilé se double en latin quand l'arabe l'écrit (ssba7 = الصباح, llil = الليل). Le latin et l'arabe d'un même mot ou exemple disent exactement la même chose.
- **Répétition espacée** (Leitner, boîtes 1 à 4) : un mot raté revient le lendemain (boîte 1) ; un mot réussi revient après 3, 7, puis 21 jours. Un mot compte comme raté s'il a eu au moins une erreur pendant la session.
- **Score de prononciation** : de 0 à 100. 80 et plus : « Excellent ». De 60 à 79 : « Presque ». Moins de 60 : « À retravailler ». 60 et plus compte comme réussi (Dis-le entre dans la répétition espacée comme les autres réponses, et ses scores dans `progression.scores`, 20 derniers). « Le score se trompe » inverse le résultat ; s'il fait passer un essai en réussi, sa distance s'ajoute au réglage de la voix. Calcul : essai et référence (MP3 Jamal) rééchantillonnés à 16 kHz, silence retiré (bloc de parole le plus fort ; pauses de 0,35 s au plus dans un mot, de 0,8 s dans une phrase, dont l'enregistrement s'arrête après 1,2 s de silence au lieu de 0,8), 12 MFCC toutes les 5 ms (filtres mel 80-7600 Hz, plancher à -50 dB, centrés et réduits), essai calculé avec 7 étirements de fréquence (0,82 à 1,18, voix plus grave ou plus aiguë) ; DTW, distance moyenne la plus petite ; barème 0,8 → 100, 1,3 → 80, 1,85 → 60, 2,9 → 0, après soustraction du réglage (médiane des distances de mots bien dits moins 1, entre 0 et 1,6).
- **Score précis** (`sons/prononciation.ts`) : le modèle donne, toutes les 20 ms, la probabilité de 392 sons, regroupés en 30 classes du darija (`CLASSES` : ħ, ʕ, q, x avec χ, ɣ avec ʁ…) ; sons attendus lus dans le latin (`sonsAttendus`, lettres doublées comptées une fois) ; pour chaque son, vraisemblance CTC du mot contre le même mot où ce son est remplacé par chacun des autres ou omis (`evaluer`, `repartition`) ; l'essai, réduit à sa parole (`rogner`, 0,2 s de marge), est comparé à Jamal (analysé à l'avance, sinon sur le téléphone) son par son (`comparer` : ressemblance de Bhattacharyya des répartitions, ou son nettement reconnu dans l'essai) ; moyenne pondérée (sons du darija ×3, consonnes ×1, voyelles ×0,25), 0,55 → 0, 0,95 → 100 (`BAREME_SONS`) ; son raté sous 0,7 (`SEUIL_SON`). Calibrage (`calibrageSons.test.ts`) : sur les 4 voix de test, au moins 75 % des bons mots réussissent et 78 % des mots voisins échouent (mesuré : 92/112 et 92/112) ; rendus de Jamal : 90 % et 75 % (80/84 et 63/84). Sans modèle ou en cas d'erreur, le score acoustique reprend. **Calibrage du score acoustique** (`calibrage.test.ts`, sur les MP3 Jamal des 26 mots des paires) : le même mot ralenti, plus aigu (bande 100-7000 Hz) ou plus grave dépasse 80 ; les deux mots de chacune des 14 paires restent sous 60, sous tous ces rendus. Phrases (`calibragePhrases.test.ts`, phrases des leçons futur et questions, pauses à 0,8 s) : la même phrase plus aiguë ou plus grave reste à 60 ou plus, coupée d'une pause de 0,6 s à 80 ou plus ; une autre phrase de la leçon reste sous 60 (sur les 50 phrases : même phrase 76 au moins, autre phrase 42 au plus).
- **XP** : 1 par bonne réponse, 10 par session terminée, 5 de bonus sans faute.
- **Niveaux** : 30 niveaux, les paliers de la plante, 3 par stade (Terreau, Graine, Germe, Pousse, Tige, Feuilles, Bouton, Fleur, Fruit, Arbre) : 60 XP pour le niveau 1, puis 10 XP de plus par niveau (6 150 XP pour les 30, environ 3 mois). Noms des paliers (`NOMS_PALIERS`) : Terre sèche, Terre arrosée, Terre prête ; Graine semée, Graine enfouie, La graine s'ouvre ; Ça perce !, La crosse, Germe debout ; Premières feuilles, Petite pousse, Pousse et coccinelle ; Jeune tige, Tige et tuteur, Tige solide ; Feuillage, Rameaux, Feuilles et papillon ; Premier bouton, Boutons, Bouton qui s'ouvre ; Première fleur, Floraison, Fleurs et abeille ; Fruits verts, Fruits qui mûrissent, Récolte ; Jeune arbre, Arbre, Arbre centenaire (au-delà, il le reste).
- **Quêtes** : 3 par jour, renouvelées à minuit heure locale : toujours « Termine une session du jour », plus deux tirées selon la date parmi 8 (2 sessions, sans faute, quiz, Quiz express, Chasse aux sons, 40 XP, 5 nouveaux mots, 10 mots écoutés). Les 3 faites ouvrent la théière-coffre (+60 XP, une fois par jour). Un trésor du Parcours rapporte +100 XP, une seule fois (table `bonus`, `cle` = `tresor-<étape>`).
- **Dirhams et souk** : par activité, 1 DH par bonne réponse plus un bonus de précision (10 DH sans faute, 5 avec une erreur, 2 avec deux) ; 60 par théière, 50 par trésor (tout recalculé depuis l'historique), moins les achats. Le souk ne vend que du décor, de 80 à 400 DH : jardin (oranger, olivier, rosier, palmier, figuier de Barbarie, jasmin, grenadier, arganier ; riad, ruelle de Chefchaouen, dunes, sommets de l'Atlas, port d'Essaouira, nuit étoilée ; lanterne, théière, tapis berbère, tajine ; animaux : cigogne, chat, tortue, poule beldi, moineaux, fennec, dromadaire au loin (objets marqués `animal`, dessinés du fond vers l'avant) ; 5 pots dont Tamegroute et poterie berbère) et appli (8 couleurs d'accent dont vert de l'Atlas et nuit du Sahara, erreurs toujours en rouge ; sons qraqeb, darbouka, oud et youyou synthétisés ; pétales, étoiles, feuilles de menthe, pièces de dirham ; 5 zelliges dont Meknès et chevrons de Rabat). L'article de départ de chaque rayon est gratuit (menthe, ciel, terre cuite, drapeau, sons classiques, confettis, sans zellige).
- **Jardin** : la plante a 10 stades de 3 paliers ; chaque palier occupe un tiers du stade et la plante grandit en continu avec l'XP (`gamification/jardin.ts`, `palierDe`) ; chaque palier ajoute un détail visible (terre fissurée, gouttes, trou ; graine posée, enfouie, fendue avec sa racine ; terre qui se soulève, crosse ; coccinelle, tuteur, escargot, papillon ; boutons qui s'ouvrent, abeille ; fruits verts puis mûrs, fruit tombé ; nid et oiseau sur l'arbre) ; l'arbre a sa pleine taille à la fin du niveau 30. Rebond et étincelles à chaque nouveau palier ; la terre du pot (et le terreau, l'escargot, le fruit tombé) reste immobile, seules la graine ou la plante rebondissent et se balancent (`Terre` hors des groupes animés) ; fissures, trou et cailloux suivent la courbe de la terre (`surface`), et les bosses de terre (`Bosse`) descendent sous la surface pour ne laisser voir aucun bord plat.
- **Collection et badges** : un mot vu est en bronze, en argent en boîte 3, en or en boîte 4. 66 badges (`BADGES`, une mesure et un seuil chacun, `badgeObtenu`, `avancementBadge`), calculés depuis les tables (rien de stocké) : mots vus 10 à 1 000, mots en argent et en or, record de série 3 à 100 jours, activités et sans-faute, niveau de la plante et XP, essais notés 80 ou 100 et Chasse aux sons, dialogues joués et sans faute, leçons de grammaire, Quiz express, marchandages et taxis, tampons du passeport, théières, achats au souk, mot ajouté dans « Mes mots ».
- **Série** : jours avec au moins une session. Aujourd'hui non fait ne casse rien. Une journée manquée est pardonnée si aucune autre ne l'a été dans les 7 jours ; deux jours manqués d'affilée cassent la série.
- **Genre** : sert à accorder les phrases (« toi » = nta au masculin, nti au féminin).
- **Modes** (`exercices/modes.ts`, `adapterEtapes`, appliqué dans `Session`) : sans parler, Dis-le et Dis-le en darija sont retirés (quiz et grammaire gardent 5 questions avec des Traduis), et les dialogues font choisir sa réplique parmi 4 ; sans écouter, Écoute et choisis devient Traduis, Distingue les sons est retiré, Quiz express en Traduis seuls, Chasse aux sons, Marchandage, Taxi et mode écoute grisés (« Réactiver l'écoute »), aucun son automatique (`jouerAuto`, sons de réponse muets ; les boutons Écouter restent). Pendant l'exercice, « Je ne peux pas parler / écouter maintenant » (`PasMaintenant`) passe l'étape sans la compter (une Écoute devient Traduis) et coupe le mode 15 min (`pauseParler`, `pauseEcouter`).

Phrases du marchand (`src/data/jeux/marchandage.json`) : `articles` (`id`, `nom`, `latin`, `arabe`, `prix` : 3 phrases `{ id: jeu-<article>-N, montant, latin, arabe, fr, audio }`), MP3 générés par l'Action. Paires de sons (`src/data/sons/paires.json`, hors des thèmes) : `mots` (`id` = `son-<latin>`, `latin`, `arabe`, `fr`, `audio` = `audio/<id>.mp3`, générés par l'Action) et `paires` (`a`, `b`, `sons` : le son de chacun, « rien » quand le second mot n'a pas de son à la place). Leçons de grammaire (`src/data/parler/grammaire.json`) : `lecons` (`id`, `titre`, `sousTitre`, `regle` : liste de phrases, `formes` : `{ id: gram-<leçon>-N, latin, arabe, fr, audio }`), MP3 générés par l'Action. Dialogues (`src/data/parler/dialogues.json`) : `scenes` (`id`, `titre`, `contexte`, `autre` : le personnage, `repliques` : `{ id: dia-<scène>-N, qui: moi | autre, latin, arabe, fr, audio, feminin?: { id: dia-<scène>-N-f, latin, arabe, fr, audio } }`).

L'id suit `<theme>-NNN` dans l'ordre du fichier ; `src/data/data.test.ts` vérifie le format, l'unicité (latin + arabe) et la translittération. `audio` = `audio/<id>.mp3` (et `audio/<id>-ex.mp3` pour l'exemple, s'il y en a un) : l'Action génère le MP3 s'il manque. Tant qu'il manque, ou si `audio` est vide, la voix de l'iPhone lit l'arabe.

Mot importé (1 530 entrées, thèmes 9 à 31 et fin des 8 premiers) : même format, avec parfois `"note": "Emprunt courant au français"` ; explication et exemple écrits par Claude (2026-10-13). Une même graphie latine peut désigner deux mots différents en arabe (7it = حيت « parce que » ou حيط « mur »). `data.test.ts` exige pour chaque mot une explication et un exemple complets.

Activité terminée (IndexedDB, table `sessions`, depuis la v2 ; `type` = `session`, `quiz`, `express`, `sons`, `marchandage`, `taxi`, `grammaire` ou `dialogue`, absent sur les sessions d'avant le Quiz) :

```json
{ "id": 1, "date": "2026-10-12", "xp": 27, "bonnes": 12, "mauvaises": 0, "nouveaux": 5, "type": "session" }
```

Mot ajouté (IndexedDB, table `motsPerso`, depuis la v3 ; `ajouteLe`, heure de l'ajout chez l'autre personne pour un mot reçu par lien, sans index ni migration ; les liens à trois valeurs, et ceux à cinq de la courte version avec un lieu, restent lus) :

```json
{ "id": "perso-<uuid>", "latin": "khobz", "arabe": "خبز", "fr": "pain", "creeLe": 1760300000000, "ajouteLe": 1760299000000 }
```

Favori ou signalement (IndexedDB, table `marques`, depuis la v4 ; supprimé quand il n'y a plus ni l'un ni l'autre) :

```json
{ "id": "salutations-012", "favori": true, "signale": "traduction", "date": 1760300000000 }
```

Achat du souk (table `achats`, v6) : `{ "id": "chefchaouen", "date": "2026-10-13", "prix": 150 }` ; décor choisi dans le profil (`couleur`, `zellige`, `pot`), couleur copiée dans localStorage (`darija-couleur`) pour l'appliquer avant le premier affichage (`data-couleur` sur `<html>`). Journal du jour (table `journal`, v5) : `{ "date": "2026-10-13", "ecoutes": 12, "coffre": true }` ; XP bonus (table `bonus`, v5) : `{ "id": 1, "date": "2026-10-13", "xp": 60, "raison": "coffre" }`, ajoutés à l'XP total. Sauvegarde (`darijaapp-AAAA-MM-JJ.json`) : `{ "format": "darijaapp-sauvegarde", "version": 1, "date": "…", "tables": { progression, profil, motsPerso, sessions, marques, journal, bonus } }` (`audioPerso` mis à null).

Profil : en plus des réglages, `micro` (Dis-le avec score), `parler` et `ecouter` (modes, vrais par défaut), `pauseParler` et `pauseEcouter` (fin de la pause de 15 min, ou null), `reglageVoix` (12 dernières distances de mots bien dits) et le décor du souk (`couleur`, `zellige`, `pot`, `espece`, `fond`, `objets` : liste des objets affichés, `sons`, `confettis`) et `jardinXpVu` (XP à la dernière visite de « Mon jardin », point de départ de l'animation, null avant la première), `genre` (`m`, `f` ou null = masculin), `scorePrecis` (score par sons, si le modèle est téléchargé), `derniereSauvegarde` (horodatage du dernier export, null si jamais) et `dialogues` (meilleur nombre de répliques réussies par scène). ## Pièges connus

- GitHub Pages sert l'appli dans un sous-dossier : il faut régler `base` dans `vite.config.ts` sur le nom du repo.
- Sur iPhone, le micro exige HTTPS et un geste de l'utilisateur. La lecture audio automatique ne démarre qu'après une première interaction.
- Sur Safari, MediaRecorder produit de l'`audio/mp4` : décode l'enregistrement avec `AudioContext.decodeAudioData` avant de calculer les MFCC. Ne rééchantillonne pas avec un `OfflineAudioContext` : Chrome replie les aigus (+5 dB au-dessus de 5 kHz, même MP3 à 0,9 de distance de lui-même) ; `reechantillonner` (sinus cardinal fenêtré) sert à l'appli et aux tests.
- Micro de l'iPhone : tant qu'il est ouvert, iOS baisse le son de lecture ; `enregistrer()` rend le micro à chaque fin d'enregistrement. Traitements du navigateur (annulation d'écho, réduction de bruit, gain automatique) coupés : ils déforment le spectre. Le runner GitHub n'a pas ffmpeg : « Publier » l'installe pour `calibrage.test.ts` (et `calibrageSons.test.ts`, dont onnxruntime donne des scores un peu différents selon le processeur : seuils à garder avec de la marge), qui décode dans `beforeAll` (le corps d'un `describe.skipIf` sauté s'exécute quand même). Pour tester Dis-le dans Chromium : `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=essai.wav` (un WAV qui boucle, avec du silence autour du mot).
- L'environnement cloud de Claude Code ne peut pas joindre mcofirty.github.io (proxy) : vérifier la mise en ligne par l'état du job `deploy`, pas par une requête au site.
- Safari et le service worker gardent les icônes en cache par URL : pour changer une icône, changer aussi son nom de fichier (`pot-*.png` depuis le 2026-10-13, avant `logo-*.png`), puis supprimer et réinstaller l'appli sur l'écran d'accueil.
- mms-tts-ara lit l'arabe sans voyelles (lettres arabes seules) : impossible de lui indiquer les voyelles du darija. Le journal de l'Action « Publier » affiche les textes lus : le vérifier avant de conclure.
- La voix lit le champ `arabe` : c'est lui qui fixe la prononciation entendue. Quand l'arabe d'un mot change, supprimer ses MP3 pour qu'ils soient régénérés.
- Un `backdrop-filter` (ou `filter`, `opacity`, `mask`) sur un élément en fait une racine d'arrière-plan : ses enfants ne voient plus la page derrière. Les couches de verre sont donc sur `::before`/`::after`, jamais sur l'élément `.verre` lui-même.
- Les classes de `src/index.css` vivent dans `@layer components` : hors couche, elles écraseraient les utilitaires Tailwind (une `position: relative` avait fait disparaître la barre du bas).
- Les couleurs de texte éclaircies du mode sombre (#ff6961, #2fd27f) ne supportent pas de texte blanc : tout bouton plein utilise `--accent-plein` ou `--vert-plein` (couleurs du drapeau, 5,8:1 et 7,5:1).
- `overflow-x: hidden` sur un conteneur en fait une zone de défilement : `position: sticky` à l'intérieur ne colle plus à la fenêtre. Utiliser `overflow-x: clip` (racine de `App.tsx`).
- `opacity` sur un élément `.verre` (ex. `.pressable:active`) en fait une racine d'arrière-plan : le verre devient opaque pendant l'appui. Les commandes en verre grossissent au toucher, sans opacité.
- Le Chromium de Playwright ne lit pas le H.264 (erreur 4 sur `lancement.mp4`) : pour tester la vidéo d'ouverture, servir une copie en VP9 (`ffmpeg -c:v libvpx-vp9`), sans la commiter.
- Un commit poussé par l'Action (`GITHUB_TOKEN`, `github-actions[bot]`) ne déclenche aucun workflow `push` : « Publier » est relancée par `workflow_run` à la fin d'« Audio ». Les deux Actions font un checkout de `main` et non du commit déclencheur, qui n'a pas les MP3 ajoutés entre-temps par le bot.
- Safari n'envoie pas toujours l'événement de fin de `speechSynthesis` : `parler()` (`src/audio/lecteur.ts`) a un délai de secours selon la longueur du texte, sans quoi le mode écoute resterait bloqué.
- Après la génération des MP3, mets à jour la liste des fichiers mis en cache par la PWA pour que l'audio marche hors ligne. GitHub refuse les fichiers de plus de 100 Mo : le modèle est coupé en morceaux de 45 Mo, recollés dans le navigateur. onnxruntime-node n'embarque pas ses types (`src/types/onnxruntime-node.d.ts`). Le WebAssembly d'onnxruntime-web est importé par `?url` depuis `node_modules`, gardé dans Cache Storage et donné en `blob:` (`wasmPaths`) ; un seul fil, GitHub Pages n'ayant pas l'isolation (COOP/COEP) qu'exigent les fils. Le petit modèle Allosaurus (45 Mo, essayé le 2026-10-13) n'a ni ʕ ni ħ et confondait q, kh et gh : retiré.
